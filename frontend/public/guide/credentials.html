Platform credentials

Nisaba connects with your own developer credentials on each platform. You create them once in each platform's portal, paste them into Nisaba's platform setup, and Nisaba stores them encrypted in your local database. Credentials are per company — each company has its own set.

eBay

Nisaba uses eBay's OAuth flow. From the eBay developer portal (Application keys):

Nisaba fieldWhere it comes from
client_idYour application's App ID (Client ID).
client_secretYour application's Cert ID (Client Secret). Shown once — copy it immediately.
redirect_uriMust match the Redirect URI registered on the keyset. Defaults to https://localhost:8443/ebay/callback; if you change it in the portal, change it here too.
environmentsandbox for testing, production for live. Sandbox and production are separate keysets.

After saving, Nisaba opens eBay's consent page in your browser so you can authorize the application; the resulting token is stored locally.

Before your first production call

eBay requires every production keyset to either subscribe to Marketplace Account Deletion notifications or be granted an exemption. Because Nisaba stores no eBay user data, you qualify for the exemption — walk through it once per production keyset: eBay account-deletion exemption.

Amazon (SP-API)

Nisaba uses Amazon's Selling Partner API. From Amazon's developer console (your SP-API application):

Nisaba fieldWhere it comes from
client_idYour Login with Amazon (LWA) Client ID.
client_secretYour LWA Client Secret.
refresh_tokenObtained by authorizing your seller account through the OAuth flow — the long-lived token Nisaba exchanges for access tokens.
seller_idYour merchant/seller ID from Seller Central.
regionNA, EU, or FE — pick the one your seller account lives in.
marketplace_idsThe marketplace IDs you sell in (e.g. ATVPDKIKX0DER for amazon.com). Leave empty to use the region default.

Rotate the client secret

Amazon rotates LWA client secrets on your schedule. Nisaba records when the secret was last changed and the credential-health panel warns you when it is older than the rotation window — generate a new secret in the developer console and paste it into Nisaba when prompted.

Squarespace

From your Squarespace site's Settings → Developer tools → API keys:

Nisaba fieldWhere it comes from
api_keyA Squarespace API key with Inventory and Orders permissions.
store_page_idThe ID of the store page to sync. Find it in the page's URL or via the API's store-pages endpoint.

XMR Bazaar

Nisaba fieldWhere it comes from
username / passwordYour XMR Bazaar account login.
base_urlDefaults to https://xmrbazaar.com; change only if you run a mirror.
monero_addressYour Monero receiving address — used for payments on new listings Nisaba creates.
endpointsOptional overrides for individual page paths if the site's layout changes (advanced).

Automated access

The XMR Bazaar adapter reads the site's pages directly (there is no public API). Check XMR Bazaar's terms on automated access before enabling it, and keep sync intervals gentle — aggressive polling can get your account rate-limited or banned.

Keeping credentials safe

  • Credentials are encrypted at rest with your company secret and are redacted in logs and in the diagnostics bundle.
  • Nisaba never sends credentials anywhere except the platform's own API — no telemetry, no third-party services.
  • If you rotate a credential in a portal (Amazon client secret, eBay cert ID), update it in Nisaba's platform setup; the old value stops working immediately on the platform side.
