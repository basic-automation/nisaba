What sync does (and doesn't do)

A sync cycle

Sync runs in cycles, either on the schedule you configure per company or when you trigger one manually from the dashboard. Each cycle, per company:

  1. Pull. Each enabled platform adapter fetches the current listings and quantities into the local catalog cache.
  2. Reconcile. Nisaba compares what the platforms report against its snapshots and works out the real-world changes — sales, restocks, price edits made on a platform.
  3. Resolve conflicts. When two platforms changed the same product in one cycle (a sale on eBay and a sale on Squarespace), the deltas are summed: each sale is an independent real-world event, so the canonical quantity moves by the total. Quantities are clamped at zero — stock can never go negative from reconciliation.
  4. Push. The resolved canonical quantities (and price changes you approved) are pushed back out to each platform's listings.

Dry run first

A dry run performs the pull and reconcile steps and reports every change it would have made — without pushing anything. Use it whenever mappings changed, after adding a platform, or any time a result looks surprising. The reported changes are exactly what the next real cycle would do, so a clean dry run means a safe real run.

What sync does NOT do

  • It never deletes your local data. Switching or leaving a company does not delete its database; failed cycles log errors instead of wiping state.
  • It never invents mappings. An unmatched listing is reported, not silently merged into a random product.
  • It never touches disabled platforms. Flip a platform off and its listings are left exactly as they are — no pulls, no pushes.
  • It never sends your data anywhere but the platforms. There is no telemetry, no cloud dashboard, no third-party analytics. The only network traffic is your adapters talking to the marketplaces, plus update checks if enabled.
  • It doesn't rewrite your descriptions on its own. Sync pushes quantities and prices; title/description/image edits you make in Nisaba are applied only when you explicitly publish them to a listing.
  • It doesn't bypass platform rules. If a platform rejects a push (rate limit, policy, validation), the cycle records the failure and moves on — it does not retry aggressively or hammer the API.

Vendor sync and plugins

Alongside marketplace sync, vendor sync runs your enabled vendor plugins (dropshippers, suppliers) on their own schedules, refreshing the vendor catalog cache the product views draw from. Plugin run history and per-plugin schedules live in the Vendors view — if a vendor's data looks stale, check there first.

Sync is one-way by design per field

Quantities flow platform → canonical → platforms. If you edit a quantity directly on eBay's website between cycles, the next cycle treats that as a real sale/restock and propagates it everywhere. Make quantity edits in Nisaba (or accept that platform-side edits win), not both.
