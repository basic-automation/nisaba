Troubleshooting

Where to look first

  • Logs view (sidebar → Logs) — every sync cycle, adapter call, and error lands here with timestamps. Filter by company or platform.
  • Notifications (sidebar → Notifications) — failed cycles, credential warnings, and backup failures surface here.
  • Credential health — the panel on each platform's setup flags expired tokens, secrets past their rotation window, and unreachable endpoints before you run a sync.
  • Plugin run history (Vendors view) — per-plugin schedules and recent runs; start here when vendor data looks stale.

Common problems

eBay OAuth fails or loops back to the login page

The redirect_uri in Nisaba must match the Redirect URI registered on the eBay keyset exactly (scheme, host, port, path). The default is https://localhost:8443/ebay/callback. Also confirm you're using the right keyset for the environment — sandbox credentials never work against production and vice versa.

Amazon calls fail with auth errors

The usual cause is a rotated LWA client secret: generate a new one in the developer console and paste it into Nisaba. If the refresh token itself was revoked (account password change, app permissions changed), re-run the OAuth authorization to get a fresh refresh token.

Squarespace sync reports "store page not found"

The store_page_id is wrong or the API key lost its Inventory permission. Re-check the page ID in the page URL and regenerate the key with Inventory + Orders scopes if needed.

XMR Bazaar sync returns garbage or nothing

The site's HTML layout probably changed — the adapter reads pages directly. Check the endpoints overrides in the platform setup, lower the sync frequency for a day (you may be rate-limited), and re-read their terms on automated access.

Quantities changed somewhere I didn't expect

Run a dry run and read it line by line: it shows exactly which listing pushed which change to which product. Nine times out of ten this reveals a wrong mapping — fix the link, not the number.

"Database is locked" or the app won't start

Another Nisaba process (or a crashed one) still holds the database. Close all Nisaba windows, wait a few seconds, and relaunch. If it persists, check for a stray process in your task manager. Your data is safe — and there's a pre-migration backup in the backups folder if you need to restore.

Config errors on startup

If you hand-edited config.toml, validate the TOML syntax (a missing quote or bracket is the classic). Nisaba falls back to defaults for unknown keys but fails loudly on malformed files — the Logs view shows the exact line.

Reporting a bug

Go to Settings → About → Export diagnostics. This writes a zip containing recent logs, app/OS/platform versions, and your configuration with all secrets redacted — secret values are replaced with [REDACTED] before the zip is written. Attach it to your bug report. Five known secret values are asserted absent from every bundle by automated tests, so you can trust the redaction.
